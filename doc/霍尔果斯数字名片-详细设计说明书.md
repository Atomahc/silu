**1. 引言**

**1.1 编写目的**

本文档旨在对霍尔果斯市“数字名片”系统进行详细设计说明。基于《霍尔果斯数字名片-概要设计说明书.md》中确定的“插画长卷叙事 + 6大分类指标分析”架构，结合项目实际代码实现（前端框架基于 Vue 3 + Vite 搭建），详细描述系统的组件划分、状态管理、核心交互逻辑、动画实现方案及数据渲染机制，并涵盖后端接口设计、数据库设计以及线上部署与维护规范。本说明书是前后端开发、代码维护、系统部署及后续迭代的直接参考依据。

**1.2 项目背景**

本项目旨在构建“一中枢、一门户”的城市级数字底座，数字城市名片作为一期项目的对外展示窗口，以可横向滚动的“数字城市长卷”为核心展现形式。由于需求调整，已取消原三维CIM方案，采用纯前端 H5 Canvas 及 CSS Transform 技术实现流畅的长卷展示与热点数据交互。系统面向来访领导考察、招商推介、汇报演示、大屏展示等场景。

**1.3 术语与定义**

*   **Vue 3 Composition API**：Vue 3 的核心 API，采用 `<script setup>` 语法进行逻辑组织。
*   **长卷容器 (Scroll Container)**：通过 CSS `overflow-x: auto` 与自定义拖拽逻辑实现的横向插画展示区。
*   **动态组件 (Dynamic Component)**：使用 `<component :is="...">` 根据状态动态渲染的面板模块。

**2. 系统前端架构设计**

**2.1 项目目录与技术栈**

本项目位于 `/data/data/com.termux/files/home/porject/silu`，采用现代前端工程化工具 Vite 构建：
*   **核心框架**：Vue 3 (`^3.4.0`)，全部采用 `<script setup>` 组合式 API。
*   **构建工具**：Vite (`^5.0.0`)，提供极速的模块热更新（HMR）。
*   **组件结构**：`src/App.vue` 作为根容器组件，按功能拆分为业务组件存放在 `src/components/` 目录下（如 `DataBox.vue`, `Panel0.vue` 等）。独立图文 HTML 内容存放在 `src/html/` 中，通过 `?raw` 方式导入。

**2.2 组件树结构**

```text
App.vue (根容器)
 ├─ Header (顶部品牌栏，包含标题、动态场景名称、时间与天气)
 ├─ ScrollHandle (左右滚动控制轴柄)
 ├─ ScrollContent (长卷核心区域，包含5大叙事主题场景)
 │   └─ PanoramicContainer
 │       ├─ panoramic-bg (长卷底层背景图，5760×960)
 │       ├─ DataBox / DataBoxIndustry / DataBoxGovernance (悬浮数据小面板)
 │       └─ MapMarker (建筑热点标注组件，列表渲染)
 ├─ MarkerModal (热点详情弹窗：图文、政策解读、视频、大数字)
 ├─ RightPopup (右侧指标浮层)
 │   └─ Dynamic Component -> Panel0 ~ Panel5 (六大分类指标数据图表)
 └─ Footer (底部分类导航栏，6大分类入口Tab)
```

**3. 核心功能详细设计**

**3.1 长卷物理滚动与拖拽实现**

长卷的横向浏览是系统的核心交互。长卷总览划分为5大场景，呈现霍尔果斯演进脉络：驿站溯源（暖金复古）、口岸脉动（深蓝沉稳）、货通四海（活力橙）、产业新城（翡翠绿）、智慧未来（科技紫）。
*   **轴柄悬停自动滚动**：通过 `startScroll` 和 `stopScroll` 方法，利用 `requestAnimationFrame` 以 `15px/帧` 的速度动态修改 `scrollContainer.value.scrollLeft`。
*   **鼠标拖拽与滚轮支持**：在 `scroll-content` 容器上绑定 `@mousedown="startDrag"` 与 `@wheel` 事件，结合全局的 `mousemove` 和 `mouseup` 事件，计算水平偏移量（`(e.pageX - startX) * 1.5` 的摩擦系数），更新滚动条位置。拖拽时添加 `.is-dragging` 类，禁用内部元素的指针事件（`pointer-events: none`）以防止误触热点。实现防越界控制，确保到达首尾时停止。

**3.2 特色建筑热点交互与数据模型 (MapMarker)**

在5大场景的标志性建筑上叠加交互热区，以微光圆点标识（颜色匹配场景情绪色）。
*   **热点场景与内容映射**：
    1. **驿站溯源**：六代国门（图文+历史沿革，如1881年正式通关）、古驿站遗址（图文路线图）。
    2. **口岸脉动**：公路口岸通关区（车道通关重车数大数字）、中欧班列（图文线路图）、经济开发区（图文）。
    3. **货通四海**：自贸区（图文+政策解读）、中哈合作中心（图文商贸实景）。
    4. **产业新城**：产业园区（全景图文+入驻企业大数字）、城市天际线（写字楼经济活力图文）。
    5. **智慧未来**：智慧治理指挥中心（图文+调度视频片段）、未来规划蓝图（图文线框图）。
*   **数据结构**：
    ```javascript
    { 
      id: 1, 
      scene: '驿站溯源', // 归属场景
      x: 5.8, y: 50.5, // 相对长卷的百分比坐标
      title: '六代国门', 
      type: 'html', // 类型标识：html/video/number
      bgImg: './laby1.png', // 背景底图
      htmlContent: marker1Html // 通过 ?raw 导入的静态内容
    }
    ```
*   **交互逻辑**：热点采用绝对定位。鼠标悬停时圆点放大并提示名称；点击后将 `activeMarker` 置为当前对象，同一时间仅展示一个弹窗卡片；点击外部区域自动关闭。微光浮动动画通过 `@keyframes floatUpDown` 实现 2.5s 周期浮动。

**3.3 场景指标浮层与底部分类导航 (Right Popup & Footer)**

独立于长卷热点的数据分析面板，通过页面底部的 6 大分类导航条唤起。
*   **分类体系与面板组件映射**：
    记录 `currentNavIndex` (0-5)，使用 `<component :is="panels[currentNavIndex]">` 动态加载 ECharts 视图：
    *   `Panel0` (数字党建)：天池英才引进（年度累计折线）、招聘总人数（大数字+年度新增折线）、招聘企业数（柱状图）等。
    *   `Panel1` (数字政务)：政务服务满意度/办结率（折线图）、平均办件天数（环比）、案件总数（折线图）。
    *   `Panel2` (数字经济)：地区生产总值/社消零总额（柱状图+同比）、外贸进出口总额（折线图+同比）、中欧班列/重车通关数（柱状图）。
    *   `Panel3` (数字社会)：在校学生数（趋势图）、医院/床位数（大数字+折线）、空气质量优良率（折线图）。
    *   `Panel4` (数字文化)：旅游人数/景区总收入（折线图+同比）、景区总游客量（柱状图）。
    *   `Panel5` (平安霍尔果斯)：车/班列放行与出入境数（柱状图）、边民备案（折线图）、超期案件数（占比环形图）。
*   **出场动画**：外层包裹 `<transition name="slide-right">`，滑出动画时长控制在 300ms 内，从画卷右下方滑出。

**3.4 顶部品牌栏 (Header)**

*   **内容展示**：左侧展示固定标题，中间基于长卷的 `scrollLeft` 实时计算当前视口所处的场景区间，动态展示对应的“场景名称”。右侧展示实时时间与天气。
*   **时间跳动**：在 `onMounted` 钩子中初始化 `setInterval`，每 1000ms 刷新 `currentTime` 驱动时间跳动。

**3.5 开场进场动画序列**

系统启动时，具有强烈的视觉仪式感：
*   通过 `triggerScrollAnimation` 方法，控制 `isOpening` 和 `isOpened` 状态变量。
*   **轴柄展开**：`@keyframes handleLeftExpand` 与 `handleRightExpand`，在 3.6s 内使用 `cubic-bezier(0.25, 0.1, 0.25, 1)` 缓动曲线将轴柄从屏幕中央向两侧推开。
*   **长卷物理伸展**：`@keyframes scrollPhysicalExpand` 控制 `.scroll-content` 的宽度从 `0.1vw` 伸展至 `100%`，结合 `scrollContentFadeIn` 实现模糊变清晰的渐显效果。

**4. 后端接口设计**

**4.1 接口规范与鉴权**

*   **协议规范**：前后端分离架构，基于 HTTP/1.1 或 HTTP/2 的 RESTful API 规范，数据传输格式统一为 `application/json`。
*   **接口鉴权**：针对系统大屏端数据拉取，采用 `Token` 鉴权机制。前端在每次请求头中携带 `Authorization: Bearer <token>` 验证身份，Token 由统一身份认证系统分发。
*   **响应结构封装**：
    ```json
    {
      "code": 200,          // 业务状态码 (200: 成功, 401: 未授权, 500: 服务器异常)
      "message": "success", // 响应描述
      "data": { ... },      // 具体业务数据 payload
      "timestamp": 1695123456789
    }
    ```

**4.2 核心API定义**

为了满足大屏右侧 6 大分类指标的数据渲染，后端按“分类聚合”的方式提供接口，降低请求频率。

*   **接口：获取指定分类下的核心指标集合**
    *   **路径**：`GET /api/v1/indicators/category/{categoryId}`
    *   **参数**：
        *   `categoryId` (Path): 分类标识（如 `digital_party`、`digital_economy` 等）
    *   **响应示例**：
        ```json
        "data": {
           "categoryName": "数字经济",
           "indicators": [
              {
                 "indicatorCode": "GDP_001",
                 "indicatorName": "地区生产总值",
                 "type": "bar_with_line", // 图表类型
                 "currentValue": 250.5,
                 "unit": "亿元",
                 "yoy": "5.2%", // 同比
                 "seriesData": [
                    {"time": "2026-Q1", "value": 50},
                    {"time": "2026-Q2", "value": 100}
                 ]
              }
           ]
        }
        ```
*   **数据自动刷新与容错**：前端在浮层保持打开期间，通过 `setInterval` 每 5分钟（300,000ms）自动静默拉取一次增量数据更新。若 API 请求超时（设定2秒限制）或无数据时，前端指标卡片显示“--”；断网时读取上一次成功的应用级缓存数据。

**5. 数据库设计**

**5.1 数据流转架构**

数字名片后台不直连各委办局的业务库，而是依赖于“数据协同调用中枢”提供清洗好的结果数据。数据落库后由后台服务按前台接口要求组装返回，并在后端引入 Redis 级缓存缓解查询压力（缓存 5 分钟，与前端刷新周期一致）。本系统采用关系型数据库（如 PostgreSQL/MySQL 或兼容的国产数据库 GaussDB/DM8）。

**5.2 核心表结构设计**

*   **1. 指标配置表 (`t_indicator_config`)**：定义 6 大分类下各个指标的元数据与展示方式。
    | 字段名 | 物理字段 | 数据类型 | 描述 |
    | --- | --- | --- | --- |
    | 主键ID | `id` | BIGINT | 主键，自增 |
    | 指标编码 | `indicator_code` | VARCHAR(64) | 唯一业务编码，如 `GDP_001` |
    | 指标名称 | `indicator_name` | VARCHAR(128) | 如“地区生产总值” |
    | 所属分类 | `category_id` | VARCHAR(64) | 所属大类（如 `digital_economy`） |
    | 图表类型 | `chart_type` | VARCHAR(32) | 前端图表映射：`number`, `line`, `bar`, `pie` |
    | 数据来源 | `data_source` | VARCHAR(128) | 数据提供委办局（如“发改委”） |
    | 状态 | `status` | TINYINT | 1:启用, 0:停用 |
    | 更新时间 | `update_time` | DATETIME | 记录更新时间 |

*   **2. 指标事实数据表 (`t_indicator_data`)**：存储清洗后的指标统计数值。
    | 字段名 | 物理字段 | 数据类型 | 描述 |
    | --- | --- | --- | --- |
    | 主键ID | `id` | BIGINT | 主键，自增 |
    | 指标编码 | `indicator_code` | VARCHAR(64) | 关联配置表编码 |
    | 统计周期 | `period_type` | VARCHAR(16) | 统计维度：`day`, `month`, `quarter`, `year` |
    | 统计时间 | `period_time` | VARCHAR(32) | 对应周期的时间标识（如 `2026-08`, `2026-Q3`） |
    | 指标数值 | `indicator_value` | DECIMAL(18,4) | 核心指标值 |
    | 同比/环比 | `ratio_value` | VARCHAR(32) | 同比或环比字符串（如 `+5.2%`） |
    | 创建时间 | `create_time` | DATETIME | 数据同步落地时间 |

**6. 线上环境部署与配置**

**6.1 前端部署配置 (Nginx)**

*   **构建**：前端通过 `npm run build` 生成生产环境静态资源，存放在 `dist/` 目录。
*   **Nginx 配置**：部署在麒麟 OS V10 系统的 Nginx 中，开启 Gzip 压缩，配置路由重定向处理 Vue Router 的 History 模式。
    ```nginx
    server {
        listen       80;
        server_name  card.horgos.gov.cn; # 示例域名或内网IP

        # 开启 Gzip 压缩，加快长卷分层图片和JS的加载速度
        gzip on;
        gzip_types text/plain application/javascript text/css image/svg+xml;

        location / {
            root   /usr/share/nginx/html/digital-card;
            index  index.html index.htm;
            try_files $uri $uri/ /index.html;
        }

        # 接口反向代理至后端服务集群
        location /api/ {
            proxy_pass http://backend_server_cluster;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }
    }
    ```

**6.2 后端与中间件配置**

*   **运行环境**：后端服务部署于麒麟 OS，运行在 东方通 TongWeb 或 Tomcat 中，采用 JDK 1.8+。
*   **缓存配置 (Redis)**：开启 Redis 服务，用于缓存 API 的查询结果，防止大屏高频轮询压垮数据库。缓存 Key 策略：`indicator:{categoryId}`，过期时间 (TTL) 设为 300 秒。
*   **网络要求**：服务端所在政务外网区需要开通与“数据协同调用中枢”网闸的通讯白名单，保障数据按时回流。

**7. 系统维护与监控**

**7.1 日志与监控预警**

*   **操作日志与异常日志**：后端通过 AOP 切面统一拦截异常并记录至日志中心，输出到 `/logs/digital-card/` 目录下，按天滚动分割（Logback/Log4j2）。
*   **性能监控**：对于关键的 `/api/v1/indicators` 接口，在 Nginx 或网关层配置超时预警（当响应时长超过 2 秒时，触发慢请求记录）。
*   **前端异常捕获**：Vue 中配置 `app.config.errorHandler`，捕获渲染异常及网络超时，将异常上报至监控接口，实现全链路追踪。

**7.2 日常维护与数据备份**

*   **静态资源更新**：当需要替换数字长卷中的背景图（如更新自贸区实景图）或增补热点内容时，前端替换对应 `public/` 或 `src/assets/` 下的资源并重新发布构建产物即可，不涉及业务系统停机。
*   **数据库备份策略**：通过数据库定时任务（如 MySQL 的 `mysqldump` 脚本 + Crontab），每天凌晨 02:00 进行 `t_indicator_config` 和 `t_indicator_data` 的全量备份，保留 30 天的备份副本，符合数据安全管理规范。

**8. 响应式与全屏适配机制**

*   **大屏适配**：支持 1920×1080、2560×1440、3840×2160 等分辨率大屏展示。确保正文字号不小于14px，大数字不小于48px。
*   **全屏模式**：提供全屏切换功能，监听 `isFullScreen` 状态并为 `document.documentElement` 增删 `is-fullscreen-mode` 类。结合 `window.updateRem()` 方法基于视口动态计算 `REM`，确保 UI 面板与图表完美缩放。热点定位与背景均采用 `%` 与 `rem` 混合布局，防止图像变形（`object-fit: contain`）。
